# 大数加法与大整数斐波那契：算法与实现说明

## 1. 问题

斐波那契数列增长极快：`F(93)` 已经超出 Java `long`（64 位有符号）的上限，
`F(800)` 有 167 位。原生定长整数类型存不下，必须自己做高精度运算。

（在 Python 里 `int` 本身就是任意精度的，所以「怎么算」不是问题；
但「手写一份大数加法」本身是原仓库那段 Java 代码的贡献，
这个技能把它保留了下来，见第 4 节。）

## 2. 大数加法原理

高精度整数加法的本质是「小学竖式加法」：

1. 两个数**从低位到高位**逐位相加（不是从高位——那才是竖式的书写顺序，程序要反过来做）。
2. 每一位：`和 = 左位 + 右位 + 进位`，`当前位 = 和 % 10`，`新进位 = 和 // 10`。
3. 较短的数高位按 `0` 补齐。
4. 最后若还有进位，把它补到最高位。

复杂度：位数 `n` 的一次加法是 `O(n)`。

### 表示法的选择

| 表示法 | 加法写法 | 单次加法复杂度 |
|--------|----------|----------------|
| 高位在前（人读法） | 结果要**往队首插入**每个数位 | `O(n²)` |
| 低位在前（机器法） | 结果**往队尾追加**每个数位 | `O(n)` |

原 Java 实现用的是「高位在前 + `sb.insert(0, ...)`」，每加一位都要把整个串往后挪一次。
技能版改成「低位在前 + 追加」，结果完全相同，但 N 可以开到十万级。

## 3. 斐波那契递推

```
F(1) = 1,  F(2) = 1,  F(n) = F(n-1) + F(n-2)
```

只需要滚动维护两个值 `first` / `second`，不必保存整条数列。
原 Java 版用 `while (i++ <= limit)`，技能版改写成等价的 `for` 循环，
下标语义不变。

## 4. 两种引擎

| 引擎 | 实现 | 用途 |
|------|------|------|
| `native` | Python 内置 `int`（任意精度） | 默认，快 |
| `manual` | `Num` 字符串大数加法 | 保留原 Java 的核心算法 |

`manual` 引擎的存在意义不是性能，而是**保留这段手写高精度实现本身**，
并给它一个可以对照验证的基准——Python 原生 `int` 就是天然的参考实现。
`--selftest` 会逐项交叉验证两者（n=1..300，以及求和结果）。

## 6. 行为差异（需要注意）

1. **前导零会被规范化。**
   原实现 `"0000" + "1"` 的结果是 `"0001"`（前导零原样保留）；
   技能版结果是 `"1"`。数学上等价，但字符串不等价。

2. **只支持非负数。**
   原实现也没做负数支持（`Num.add` 直接把 `-` 当数字位处理，结果是错的）。
   技能版显式拒绝负数输入并报错，而不是给出错误结果。

3. **`""` 视作 0。**
   原实现用 `num.length() == 0` 判断空串并直接返回另一个操作数；
   技能版把空串规范化为 0，行为一致但更显式。

4. **类名与语言。**
   `Num` 从独立类变成 `fibonacci.py` 里的一个类（技能要求单文件自包含）；
   从 Java 移植到 Python，去掉了 package、继承和 getter/setter 样板。

5. **新增 `minus_one()`。**
   求和恒等式 `sum(F(1..N)) = F(N+2) - 1` 需要减一；
   原实现没有减法，且不能靠加负数实现（见差异 2），所以单独实现了一个借位减一。

6. **输出行尾符跟随平台。**
   原 Java 版 `println` 在 Windows 上输出 CRLF；技能版写 `"\n"`，由 Python 的
   文本模式翻译成平台行尾符，结果与原版**逐字节一致**（已用 `cmp` 验证 800 行全等）。

## 7. 自检覆盖的用例

`--selftest` 跑以下用例，全过才退出码 0：

- **已知值**：`F(1)=1`、`F(2)=1`、`F(3)=2`、`F(10)=55`、`F(20)=6765`、
  `F(30)=832040`、`F(50)=12586269025`、`F(100)=354224848179261915075`
  （F(100) 已经超出 64 位，用字符串比对）。
- **递推恒等式**：`F(n) + F(n+1) = F(n+2)`，n 取 1..200。
- **求和恒等式**：`sum(F(1..n)) = F(n+2) - 1`，n 取 1, 2, 3, 10, 50, 100, 500。
- **双引擎交叉验证**：n=1..300 逐项比对 `manual` 与 `native`，并比对求和结果。
- **进位链**：`999 + 1 = 1000`（连续进位）。
- **前导零**：`000123 + 0 = 123`。
- **减一**：`1000 - 1 = 999`、`10 - 1 = 9`。
- **空串视作 0**：`9999 + 0 = 9999`、`0 + 1 = 1`。

## 8. 性能实测

本机实测（Python 3.12，Windows）：

| 任务 | 耗时 |
|------|------|
| 输出 F(1)..F(800) | < 0.3 秒 |
| `sum(F(1..20000))`（4178 位） | < 0.1 秒（native 引擎） |
| `sum(F(1..20000))`（manual 引擎） | 约 1 秒 |

位数估算：`F(n)` 的十进制位数 ≈ `n * log10(φ) - log10(√5)`，其中 `φ ≈ 1.618`，
即每项约 0.209 位。

## 9. 斐波那契数列背景

`F(1) = 1`、`F(2) = 1`、`F(n) = F(n-1) + F(n-2)`。

常用恒等式（部分已用于自检）：

- `F(n) + F(n+1) = F(n+2)`
- `sum(F(1..N)) = F(N+2) - 1`
- `sum(F(1..N) * F(i)) = F(N) * F(N+1)`（加权求和）
- `F(n)` 是最接近 `φ^n / √5` 的整数
